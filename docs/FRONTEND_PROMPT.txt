1. TIZIM NIMA QILADI
==================================================================

Xususiy kompaniya dorilarni yuk ko'rinishida oladi, markaziy omborga kirim qiladi, hududlardagi
dilerlarga jo'natadi, dilerlar esa dorixonalarga sotadi. Sotuvni DILER kiritadi, dorixona tizimga
kirmaydi. Maqsad: qaysi hududda qancha dori qolgani va qancha sotilganini ko'rish, rahbarga
tahlil berish.

  Yetkazib beruvchi -> Markaz (kirim) -> Diler (qabul, qoldiq) -> Dorixona (diler kiritgan sotuv)

Atamalar (interfeysda aynan shular ishlatiladi):
  Markaz        Markaziy ombor. Yagona, hududga tegishli emas.
  Diler         Hududdagi vakil. Viloyat (region) va ixtiyoriy tuman (district) manzili bor.
  Dorixona      Dilerdan oladigan mijoz. Tizim foydalanuvchisi emas.
  Hudud         Viloyat (14 ta, tayyor yuklangan).
  Tuman         Tuman yoki shahar (209 ta, tayyor yuklangan).
  Partiya       Bir dorining bir xil raqam va yaroqlilik muddatiga ega to'plami (batch).
  Jo'natma      Markaz va diler orasidagi tovar harakati (shipment).
  Inventarizatsiya  Qoldiqni qo'lda sanash (stock count).

Asosiy qoidalar:
  - Qoldiq faqat amallar orqali o'zgaradi va har biri jurnalga yoziladi. Qo'lda tahrir yo'q.
  - Qoldiq partiya darajasida yuritiladi va manfiy bo'lmaydi.
  - Sotuv tahrirlanmaydi va o'chirilmaydi: xato sotuv bekor qilinadi (reverse) va qayta kiritiladi.
  - FEFO: sotuvda partiya tanlanmasa, muddati eng yaqin partiyadan avtomatik yechiladi.
  - Kirim narxi kompaniya siri: Diler uni hech qachon ko'rmaydi (API null qaytaradi).
  - Sotuv hududi dorixona manzili bo'yicha, qoldiq hududi diler manzili bo'yicha hisoblanadi.
  - Sotuv SOF hisoblanadi: bekor qilinganlar kirmaydi, tasdiqlangan dorixona qaytarishlari ayriladi.
  - Pul birligi: so'm (backendda valyuta maydoni yo'q, hamma summani so'mda ko'rsat).

Mobil ilova alohida jamoa tomonidan yoziladi. Sen faqat web ilovani yozasan, lekin Diler ham
webdan foydalanadi, shuning uchun Diler ekranlari telefonda to'liq ishlashi shart.

3. API UMUMIY KELISHUVLARI
==================================================================

Asosiy yo'l:     https://pharm-api.agorarestobar.uz/api/v1
Sarlavhalar:     Authorization: Bearer <accessToken>
                 Accept-Language: uz, uz-Cyrl yoki ru (har bir so'rovda joriy tilni yubor, standart uz)
JSON:            maydonlar camelCase
Identifikator:   GUID satr
Sana:            DateOnly, "2026-11-02"
Vaqt:            ISO 8601, ekranda Toshkent vaqtida ko'rsat (UTC+5)
Enum:            matn, masalan "InTransit"
Bugungi sana:    backend Toshkent vaqti bilan hisoblaydi, frontend ham shunday hisoblasin
Javob kodlari:   POST yaratish 201, amal va tahrir 200 (yangilangan obyekt bilan),
                 logout, change-password, reset-password, DELETE, notification read: 204 (tanasiz)

Sahifalash (hamma PagedResult ro'yxatlar):
  ?page=1&pageSize=20&search=...
  pageSize eng ko'pi 200, undan kattasi jimgina 200 ga tushiriladi.
  Tartiblash serverda yo'q. Server tartibini saqla, ustun bo'yicha sort qo'shma
  (faqat analitika jadvallari to'liq keladi, ularda sort va sahifalash client tomonda).

O'chirish:
  DELETE yozuvni o'chirmaydi, isActive=false qiladi. Tugma nomi "Faolsizlantirish" bo'lsin.
  Qayta faollashtirish: PUT bilan isActive=true.
  PUT to'liq obyekt kutadi: isActive yuborilmasa true bo'ladi, shuning uchun tahrir formasi
  mavjud isActive qiymatini doim yuborsin. Dilerda serviceRegionIds va serviceDistrictIds ham
  to'liq yuborilsin, yuborilmasa tozalanib ketadi.

isActive bo'yicha filtr faqat dealers ro'yxatida bor. Boshqa ro'yxatlar faol va nofaolni birga
qaytaradi. Tanlash maydonlarida (select) nofaol yozuvlarni client tomonda yashir, ma'lumotnoma
jadvalida esa holat ustuni bilan ko'rsat.

Tumanlar 209 ta, pageSize esa 200: tumanlarni doim regionId bilan so'ra.

Fayl yuklab olish (Excel):
  fetch + Authorization bilan blob ol, keyin brauzerda saqlat. Oddiy <a href> ishlamaydi.
  Content-Disposition sarlavhasi CORS'da ochilmagan, shuning uchun fayl nomini frontendda ber:
    exports/sales     -> sotuvlar.xlsx
    exports/stock     -> qoldiq.xlsx
    exports/expiring  -> muddati-yaqin.xlsx
    exports/dealers   -> dilerlar.xlsx

4. KIRISH VA SESSIYA (ENG MUHIM QISM, ANIQ SHUNDAY QIL)
==================================================================

Ochiq ro'yxatdan o'tish va parolni tiklash yo'q. Birinchi Admin serverda yaratilgan, qolgan
foydalanuvchilarni Admin qo'shadi. Parolni unutgan foydalanuvchiga: "Administratorga murojaat qiling".

POST /auth/login    { phone, password } -> AuthResponse
POST /auth/refresh  { refreshToken }    -> AuthResponse
POST /auth/logout   { refreshToken }    -> 204 (access token ham kerak)
GET  /auth/me                           -> MeDto
POST /auth/change-password { currentPassword, newPassword } -> 204

Telefon formati: +998XXXXXXXXX. Formada niqob ishlat va shu ko'rinishda yubor.
Access token 30 daqiqa (expiresIn soniyada), refresh token 30 kun.

Tokenlar: accessToken va refreshToken localStorage'da saqlanadi (barcha tablar bir xil ko'rishi uchun).
Ilova ochilganda token bo'lsa GET /auth/me chaqir.

Refresh token BIR MARTALIK. Eski token qayta yuborilsa, server bu foydalanuvchining BARCHA
sessiyalarini tugatadi. Shuning uchun:
  1. 401 kelsa va javobdagi code === "common.unauthorized" bo'lsa, refresh qil va so'rovni bir marta
     takrorla. Boshqa 401 kodlarida refresh qilma (auth.invalid_credentials, auth.invalid_refresh_token).
  2. /auth/* so'rovlarining o'zi refresh'ni ishga tushirmasin.
  3. Bir vaqtda faqat bitta refresh ketsin: bir nechta so'rov 401 olsa, hammasi bitta natijani kutsin.
  4. Bir nechta TAB uchun navigator.locks.request("pt-refresh", ...) ishlat. Qulf ichida tokenni
     localStorage'dan qayta o'qi: agar u shu tab yuborgan eski tokendan farq qilsa, boshqa tab yangilab
     bo'lgan, refresh qilma va yangi access token bilan davom et.
     Web Locks mavjud bo'lmagan brauzer uchun localStorage asosidagi oddiy qulf yoz.
  5. Yangi refreshToken ni darhol saqla.
  6. auth.invalid_refresh_token (401) yoki auth.user_inactive (403) kelsa: tokenlarni o'chir va /login ga o't.
  7. 429 (common.too_many_requests) kelsa sessiyani tugatma: login va refresh birgalikda bir IP uchun
     daqiqasiga 10 ta so'rov bilan cheklangan. Foydalanuvchiga xabar ko'rsat va keyinroq qayta urin.

Parol o'zgartirilgandan keyin barcha refresh tokenlar bekor bo'ladi: tokenlarni o'chir va /login ga yubor.
Parol kamida 8 belgi.
Logout: refreshToken bilan chaqir, tarmoq xatosi bo'lsa ham lokal tokenlarni o'chir va query keshini tozala.

6. BIZNES JARAYONLARI
==================================================================

Markaziy ombor location ID si (backendda doimiy):
  CENTRAL_LOCATION_ID = "00000000-0000-0000-0000-000000000001"
Joylashuvlar ro'yxati uchun endpoint yo'q. Tanlash ro'yxatini shunday yig': Markaz + GET /dealers dagi
har bir dilerning locationId si. Dilerning o'z locationId si: GET /dealers/{me.dealerId}.

6.1 Tizimni boshlash tartibi (bo'sh tizimda maslahat sifatida ko'rsat)
  Ishlab chiqaruvchi -> Dori -> Yetkazib beruvchi -> Diler -> Diler foydalanuvchisi -> Dorixona -> Kirim -> Jo'natma

6.2 Kirim (faqat markazga)
  Qo'lda: hujjat raqami, yetkazib beruvchi, sana, izoh va qatorlar (dori, partiya raqami, muddat, miqdor, narx).
  Bir xil dori va partiya raqami boshqa muddat bilan kelsa 409 batch.expiry_mismatch (details[0] = partiya raqami).
  Kirim tahrirlanmaydi va o'chirilmaydi. Saqlashdan oldin tasdiqlash oynasini ko'rsat.

  Excel import (multipart/form-data): file, documentNumber, supplierId, receivedOn.
  Ustunlar: "GTIN yoki dori nomi", "Partiya raqami", "Yaroqlilik muddati (YYYY-MM-DD)", "Miqdor", "Narx".
  Hammasi yoki hech narsa: bitta xato qator butun faylni rad etadi.
  400 import.failed kelsa details = [{ row, message }]: xatolarni jadval qilib ko'rsat.
  Sahifada shablonni yuklab olish tugmasi bo'lsin.

6.3 Jo'natma
  Holatlar:  Draft -> Approved -> InTransit -> Received
             Draft va Approved -> Cancelled
  Yo'nalish: Markaz -> Diler (markaz xodimi toDealerId bilan yaratadi)
             Diler -> Markaz (qaytarish: diler toDealerId SIZ yaratadi)
  Dilerdan dilerga jo'natma yo'q.

  Tugmalar (aynan shu shartlarda ko'rsat). "Markazdan" = fromLocationId === CENTRAL_LOCATION_ID:
    Tasdiqlash:      status=Draft, rol A yoki W
    Yuborish:        status=Approved; Markazdan bo'lsa rol A/W; aks holda rol D va fromLocationId o'ziniki
    Qabul qilish:    status=InTransit; Markazga bo'lsa rol A/W; aks holda rol D va toLocationId o'ziniki
    Bekor qilish:    status Draft/Approved; Markazdan bo'lsa rol A/W; aks holda rol D va fromLocationId o'ziniki
    Farqni hal qilish: item.discrepancyStatus=Open, faqat A
  E'tibor: Admin dilerning joyidan yubora yoki qabul qila olmaydi, API 403 qaytaradi.

  Yaratish formasi: qatorlarni GET /stock/balances?locationId=<joylashuv>&pageSize=200 dan tanla.
  Har qatorda dori, partiya, muddat va mavjud miqdorni ko'rsat. Bir partiya bir marta kiritiladi.
  Muddati o'tgan partiya dilerga yuborilmaydi (400 batch.expired, details[0] = partiya raqami), ularni
  tanlovdan chiqar. Dilerning markazga qaytarishida muddati o'tgani ham mumkin.
  Qoldiq yaratishda emas, YUBORISHDA kamayadi va tekshiriladi: yuborishda 409 stock.insufficient bo'lishi mumkin.

  Qabul qilish formasi: har qator uchun receivedQuantity, boshlang'ich qiymat sentQuantity.
  Miqdor farq qilsa sabab maydonini ko'rsat. HAMMA qator yuboriladi, itemId = item.id
  (aks holda 400 shipment.receive_items_mismatch). 0 yoki sentQuantity dan katta qiymat ruxsat etilgan
  va bunday qator Open farq bo'ladi. Yuborishdan oldin farqlarni ko'rsatib tasdiqlat.

  Farqni hal qilish (Admin):
    CorrectSender: jo'natuvchi qoldig'i farq miqdoriga tuzatiladi.
    AcceptAsIs:    farq yo'qotish yoki ortiqcha sifatida qabul qilinadi, qoldiq o'zgarmaydi.
  Farq = sentQuantity - receivedQuantity. Musbat bo'lsa kam kelgan, manfiy bo'lsa ortiq kelgan.

  Detal sahifasida holat vaqt chizig'ini ko'rsat: createdAt, approvedAt, sentAt, receivedAt.

6.4 Sotuv (faqat Diler kiritadi)
  POST /sales, sarlavha Idempotency-Key MAJBURIY (100 belgigacha).
  Kalit qoidasi:
    - Forma ochilganda crypto.randomUUID() bilan kalit yarat.
    - Tarmoq xatosi yoki 5xx bo'lsa natija noma'lum: formani qulfla va faqat "Qayta yuborish" tugmasini ber,
      AYNAN shu kalit va shu ma'lumot bilan yubor.
    - 4xx bo'lsa sotuv yaratilmagan: tahrir qilishga ruxsat ber, kalit o'sha qolishi mumkin.
    - Muvaffaqiyatdan keyin yangi sotuv uchun yangi kalit yarat.
    - 201 ham, 200 ham muvaffaqiyat (200 = oldin qabul qilingan).

  Forma: dorixona, sana, izoh, qatorlar (dori, miqdor, narx, ixtiyoriy partiya).
    Dorixona: GET /pharmacies, isActive=true va status Active yoki Pending bo'lganlar. Pending belgisi bilan ko'rsat.
    Sana: standart bugun, kelajak mumkin emas (400 sale.date_in_future), o'tgan sana mumkin.
    Dori: GET /stock/balances (dilerga avtomatik o'z qoldig'i) ni productId bo'yicha yig'ib ko'rsat.
    Bir dori bir sotuvda bir marta. Partiya maydoni standart "Avtomatik (FEFO)".
    Pastda jami summa = sum(miqdor x narx).
  Xatolar: 409 stock.insufficient, details[0] = productId yoki batchId, tegishli qatorni belgilab ko'rsat.
           400 pharmacy.not_available, 400 batch.expired.

  Bekor qilish: POST /sales/{id}/reverse { reason } sabab majburiy. Bekor qilingan sotuv qoldiqqa qaytadi.
  Kerakli amalni taklif qil: bekor qilib, shu ma'lumot bilan yangi forma ochish.

6.5 Inventarizatsiya
  POST /stock-counts { locationId? }: Diler va Warehouse yubormaydi (Warehouse faqat markaz),
  Admin istalgan joylashuvni tanlay oladi. Javobdagi items sanash ro'yxati (expectedQuantity).
  Sanash formasi: har qatorga countedQuantity kiritiladi, farq darhol ko'rinadi. Qatorlarni lokal saqla,
  sahifa yopilsa yo'qolmasin (sessionStorage).
  POST /stock-counts/{id}/complete { items: [{ batchId, countedQuantity }] }:
    Ro'yxatdagi HAMMA partiya yuboriladi (aks holda 400 stock_count.items_mismatch).
    Ro'yxatda yo'q, javonda topilgan partiyani GET /batches dan qo'shish mumkin.
    Yakunlangach qoldiq sanalgan miqdorga TENG bo'ladi, tasdiqsiz. Shuning uchun aniq ogohlantirish bilan tasdiqlat.
  Yakunlanganini qayta yakunlab bo'lmaydi (409 stock_count.not_in_progress).

6.6 Hisobdan chiqarish va dorixona qaytarishi
  POST /adjustments so'rov yaratadi, qoldiq faqat Admin tasdiqlaganda o'zgaradi.
  type: WriteOffExpired, WriteOffDamaged, WriteOffOther: qoldiq kamayadi.
        PharmacyReturn: qoldiq oshadi va sof sotuv kamayadi, pharmacyId majburiy.
          unitPrice'ni formada majburiy qil: API uni talab qilmaydi, lekin berilmasa dona ayriladi, summa ayrilmaydi.
          Sof sotuvga faqat diler joylashuvidagi qaytarish ta'sir qiladi, shuning uchun Admin uni diler joylashuvida yaratsin.
  locationId: Diler va Warehouse yubormaydi, Admin tanlashi mumkin.
  Partiya: shu joylashuvning qoldig'idan (stock/balances).
  Admin ro'yxatda Pending yozuvlarni tasdiqlaydi yoki rad etadi. Tasdiqda 409 stock.insufficient bo'lishi mumkin.

6.7 Dorixona
  Markaz xodimi qo'shsa darhol Active. Diler qo'shsa Pending va A/W tasdiqlaydi yoki rad etadi.
  Diler Pending dorixonasiga darhol sotishi mumkin, Rejected dorixonaga sotib bo'lmaydi.
  Diler dorixonani tahrirlay olmaydi.

6.8 Manzil tanlash
  Hudud majburiy, tuman ixtiyoriy. Tuman ro'yxati hududga bog'liq (GET /districts?regionId=&pageSize=100),
  hudud o'zgarsa tuman tozalanadi. Mos kelmasa 400 district.not_in_region.
  Dilerda qo'shimcha xizmat hududlari: serviceRegionIds, serviceDistrictIds (ko'p tanlov).

6.9 Foydalanuvchi
  Role=Dealer bo'lsa dealerId majburiy (400 user.dealer_required). Boshqa rollarda dealerId yuborilmaydi.
  Telefon band bo'lsa 409 user.phone_taken, shu maydonga xatoni qo'y.
  O'chirish yo'q: PUT bilan isActive=false. Parolni tiklash: POST /users/{id}/reset-password.

6.10 Ogohlantirishlar
  Server soatiga bir marta tekshiradi. Warehouse'ga ogohlantirish yuborilmaydi, unda ro'yxat bo'sh bo'lishi normal.
  Sarlavhada qo'ng'iroq belgisi: GET /notifications/unread-count har 60 soniyada.
  Bosilganda: read qil va o'tish:
    ExpiringBatch       -> entityId = batchId     -> hisobot: muddati yaqin
    LowStock            -> entityId = productId   -> qoldiq, shu dori filtri bilan
    ShipmentNotReceived -> entityId = shipmentId  -> jo'natma detali
    SalesNotReported    -> entityId = dealerId    -> A/E: dilerlar hisoboti; D: yangi sotuv

Har qanday xato application/problem+json, ApiProblem shaklida. Mantiq uchun code, foydalanuvchiga title
(serverdan joriy tilda keladi). Bitta markaziy apiClient ApiError tashlasin (status, code, title, errors, details, traceId).
500 xatoda traceId ni nusxalash mumkin bo'lsin. Tarmoq xatosini alohida ko'rsat ("Internet aloqasini tekshiring").

Validatsiya (400 common.validation_failed): errors { maydon: [xabarlar] }.
  Kalitlar katta-kichik harfda farq qilishi mumkin (fullName, Name, items[0].Quantity): solishtirishni
  katta-kichik harfga e'tiborsiz va qator indeksi bilan qil, react-hook-form setError ga bog'la.
  Mos maydon topilmasa formaning tepasida umumiy xato ko'rsat.
  Maydon xabarlari uchala tilda keladi, lekin ichida maydonning inglizcha nomi qolishi mumkin. Shuning uchun Zod
